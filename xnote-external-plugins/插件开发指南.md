# X-Note 外部插件开发指南

> 适用版本：X-Note v0.4.0（契约类型以仓库 `src/plugins/types.ts` 为准）

外部插件是**无构建步骤的裸 JavaScript（ESM）**：写好文件放进笔记库的 `.xnote-plugins/<插件目录>/`，就能被 X-Note 动态加载，不需要改应用代码、不需要重新编译、不需要 npm install。

---

## 一、三种使用方式

| 方式 | 操作 | 适合 |
| ---- | ---- | ---- |
| 复制目录 | 插件目录放进 `<笔记库>/.xnote-plugins/` → 「插件 → 插件中心… → ↻ 重载目录」 | 开发调试，改完点一次就生效 |
| .zip 插件包 | 「插件 → 插件中心… → ⬆ 安装 .zip 插件包」 | 分发给别人，一个文件搞定 |
| 插件中心 | 「插件 → 插件中心…」刷新列表 → 安装 / 更新 / 卸载 | 最终用户，可发现新版本 |

插件目录的位置跟着笔记库走：桌面端是笔记库文件夹下的 `.xnote-plugins/`；浏览器预览模式用 localStorage（`xnote:external-plugins`）模拟，首次运行会自动装一个 hello-world 演示插件。

## 二、最小插件

```
<笔记库>/.xnote-plugins/
└── my-plugin/            # 目录名随意，建议与 manifest.id 一致
    ├── plugin.json       # 清单
    └── main.js           # 入口（文件名可用清单的 main 字段改）
```

`plugin.json`：

```json
{
  "id": "my-plugin",
  "name": "我的插件",
  "version": "1.0.0",
  "description": "一句话说明",
  "main": "main.js"
}
```

| 字段 | 必填 | 说明 |
| ---- | ---- | ---- |
| `id` | ✅ | 插件唯一标识（建议小写 + 连字符）。设置命名空间、命令归属、插件中心判断「已安装/可更新」都按它匹配——**上架后不要再改** |
| `name` | ✅ | 显示名，出现在插件列表与菜单里 |
| `version` | 建议 | 语义化版本。插件中心里索引的版本高于本地版本才会出现「可更新」 |
| `description` | — | 列表里的说明文字 |
| `main` | — | 入口文件名，默认 `main.js`；放在子目录也可（如 `dist/main.js`） |

`main.js` 用 `export default` 导出插件对象：

```js
export default {
  manifest: { id: 'my-plugin', name: '我的插件', version: '1.0.0', description: '一句话说明' },
  activate(ctx) {
    // 注册命令 / 设置面板 / 监听编辑器
  },
  deactivate(ctx) {
    // 可选：停用清理。命令与面板由宿主按归属自动移除，这里只清自己的定时器/订阅
  },
}
```

注意：`main.js` 里的 `manifest` 才是运行时真正生效的清单，`plugin.json` 只用于扫描与安装校验——**两处 id / version 要一起改**。

## 三、生命周期

| 阶段 | 时机 | 说明 |
| ---- | ---- | ---- |
| 加载 | 应用启动、选择笔记库后、「重载目录」 | 扫描每个子目录 → 读 `plugin.json` → Blob URL import 入口 |
| `activate(ctx)` | 加载成功后 | 可以是 `async`；注册的命令立即出现在「插件」菜单 |
| `deactivate(ctx)` | 停用 / 重载 / 卸载前 | 可选。命令与设置面板会自动按插件 id 移除 |
| 失败 | 入口抛错、形状不符、清单损坏 | 只影响该插件，错误显示在「插件中心 → 已安装」列表，其他插件照常 |

宿主做了三层去重保护（同一 id 只保留一份注册、重载后丢弃上一轮迟到的注册、同一插件内重复注册同 id 命令只留一份）。副作用是：**不要在 `activate` 里长时间 `await` 之后才注册命令**——如果这期间用户点了「重载目录」，那批注册会被丢弃。

## 四、PluginContext 能力一览

| 能力 | 方法 | 说明 |
| ---- | ---- | ---- |
| `ctx.manifest` | — | 当前插件清单 |
| `ctx.storage` | `loadAll()` `readFile(path)` `writeFile(path, content)` `deletePath(path)` `getModified(path)` `reloadLibrary()` | 读写**笔记库**（只限库内路径） |
| `ctx.editor` | `active()` `getContent()` `setContent()` `getSelection()` `replaceSelection()` `insertText()` `replaceRange()` `select()` `focus()` `onChange()` | 读写当前打开的笔记 |
| `ctx.http` | `request(opts)` `postJSON(url, body, headers?, timeoutMs?)` `getJSON(url, headers?, timeoutMs?)` | 桌面端经 Rust 侧发出，不受 CORS 限制 |
| `ctx.settings` | `get(key, def)` `set(key, value)` | 插件私有配置，键为 `xnote:plugin:<id>:<key>`，值为 JSON |
| `ctx.ui` | `registerCommand` `registerSettingsPanel` `showDialog` `closeDialog` `showToast` | 菜单命令 / 设置面板 / 自定义弹窗 / 提示 |
| `ctx.log` | `ctx.log(...args)` | 带 `[plugin:<id>]` 前缀的控制台日志 |

### 4.1 编辑器读写

```js
const note = ctx.editor.active()        // { path, title, content } | null（没打开笔记时为 null）
const sel = ctx.editor.getSelection()   // { text, start, end }（无选区时 start === end）
const all = ctx.editor.getContent()     // 全文，无笔记时为空串

ctx.editor.replaceSelection('替换选区')  // 无选区则插入到光标处，光标移到插入内容之后
ctx.editor.insertText('插入')            // 光标处插入，不删选中内容
ctx.editor.replaceRange(0, 10, 'X')     // 按全文偏移替换任意区间（越界自动裁剪）
ctx.editor.setContent('# 整篇重写')      // 整体替换
ctx.editor.select(3, 8)                 // 定位选区（比如高亮刚生成的结果）
ctx.editor.focus()

const off = ctx.editor.onChange(c => console.log('正文长度', c.length))  // 返回取消订阅函数
```

几个要点：

- 所有写入都走应用同一条链路——自动保存、版本快照、`Ctrl+Z` 撤销全部生效，**插件不需要自己写文件**
- 数据源是编辑器里的当前快照；选区取不到时（比如编辑器未渲染）退化为文末零宽选区
- 千万别在 `onChange` 里无条件调用 `setContent`，那是死循环；要做联动请先比较内容

### 4.2 网络请求

```js
const res = await ctx.http.postJSON('https://api.deepseek.com/v1/chat/completions',
  { model: 'deepseek-chat', messages: [{ role: 'user', content: '你好' }] },
  { Authorization: 'Bearer ' + key })

if (!res.ok) throw new Error(`HTTP ${res.status}：${res.text}`)
const text = res.data?.choices?.[0]?.message?.content ?? ''
```

返回结构：`{ status, ok, text, headers, data }`（`data` 是解析失败的 `null` 或 JSON 结果）。默认超时 120 秒，可用第四个参数覆盖。

- 桌面端：由 Rust 侧（`tauri-plugin-http`）发请求，OpenAI 兼容接口、Gitee raw 这类**不返回 CORS 头**的服务也能直接调
- 浏览器预览模式：退回 `fetch`，会被同源策略拦截——报错信息里会明确提示「请用桌面版调用第三方 API」

### 4.3 配置存储

```js
const cfg = ctx.settings.get('cfg', { endpoint: '', key: '' })
ctx.settings.set('cfg', { ...cfg, key: 'sk-xxx' })
```

存在 localStorage：`xnote:plugin:<插件id>:cfg`。适合令牌、开关、上次选择这类小配置；容量约 5MB，不要往里塞笔记正文或大缓存。写入会触发宿主刷新设置面板。

## 五、UI：命令、设置面板、弹窗、提示

```js
activate(ctx) {
  // 1) 命令：出现在「插件」菜单
  ctx.ui.registerCommand({
    id: 'my-plugin.hello',            // 全局唯一，建议 "插件id.动作"
    title: '打个招呼',
    run: async () => {
      try {
        ctx.ui.showToast('Hello!', 'success')   // kind: success | error | info
      } catch (e) {
        ctx.ui.showToast('出错了：' + e.message, 'error')
      }
    },
  })

  // 2) 设置面板：出现在「插件 → 插件设置…」
  ctx.ui.registerSettingsPanel({
    id: 'my-plugin',
    title: '我的插件',
    render: () => window.XNoteReact.createElement(Panel, { ctx }),
  })

  // 3) 自定义弹窗：宿主只提供外壳
  ctx.ui.showDialog({
    id: 'my-plugin-tool',
    title: '我的工具',
    subtitle: '可选副标题',
    width: 720,
    render: () => window.XNoteReact.createElement(ToolPanel, { ctx }),
  })
}
```

| API | 落地位置 | 注意事项 |
| ---- | -------- | -------- |
| `registerCommand` | 「插件」菜单顶部区，按注册顺序 | `id` 全局唯一；`run` 里的异常不会被宿主吞掉，自己 `try/catch` 并 toast，否则只会在控制台报错 |
| `registerSettingsPanel` | 「插件 → 插件设置…」 | `render()` 返回 React 元素；面板 id 别用 `cloudSync`（保留给内置云同步，它挂在「同步」弹窗里） |
| `showDialog` | 居中弹窗 | 同时只保留最新一个；`width` 默认 720；点遮罩或 Esc 关闭；`ctx.ui.closeDialog()` 可主动关 |
| `showToast` | 右下角提示 | `success / error / info`，默认 info |

### 用 React（不 import）

外部插件不能 `import 'react'`。宿主把同一个 React 实例挂在 `window.XNoteReact`，用 `createElement` + hooks 即可：

```js
function Panel({ ctx }) {
  const { createElement: h, useState } = window.XNoteReact
  const [cfg, setCfg] = useState(ctx.settings.get('ui', { sign: '' }))
  return h('div', null,
    h('label', null, '签名：'),
    h('input', {
      value: cfg.sign,
      onChange: e => setCfg({ ...cfg, sign: e.target.value }),
    }),
    h('button', {
      onClick: () => { ctx.settings.set('ui', cfg); ctx.ui.showToast('已保存', 'success') },
    }, '保存'),
  )
}
```

> 手写 `createElement` 很快会变得难读。插件复杂时建议在本地用 esbuild / rollup 把 JSX + 多文件打包成**单个 ESM 文件**，并把 `react` 标记为 external、改成从 `window.XNoteReact` 取——产物丢进插件目录即可运行。

## 六、运行环境限制（最容易踩的坑）

| 限制 | 原因 | 应对 |
| ---- | ---- | ---- |
| 不能 `import './util.js'` | 入口通过 Blob URL import，没有模块基址，相对路径解析不了 | 打包成单文件 |
| 不能 `import 'react'` / 任何 npm 包 | 没有 Node 解析、没有依赖安装步骤 | 用 `window.XNoteReact`；第三方库打包进单文件 |
| 不支持 JSX / TypeScript | 浏览器直接执行源码，没有编译步骤 | 打包时编译，或直接写 `createElement` / 纯 JS |
| 只能用 `ctx.storage` 访问文件 | 宿主只暴露笔记库读写，插件没有任意文件系统权限 | 需要别的路径就让用户选库或走 `ctx.http` |
| 浏览器模式受 CORS 限制 | 走的是普通 `fetch` | 桌面端使用；或要求目标服务允许跨域 |

可以放心用的：`setTimeout` / `setInterval`、`crypto`、`canvas`、`URL`、`Blob`、`navigator` 等浏览器 API。不建议：直接改 `document` 里应用的 DOM 结构、覆盖 `window` 上的全局对象（升级后极易失效）。

## 七、调试

1. 插件目录放进 `<笔记库>/.xnote-plugins/`
2. 「插件 → 插件中心… → ↻ 重载目录」——每次改完代码都点这个（不用重启应用）
3. 「插件」菜单出现你的命令；「插件 → 插件设置…」出现你的面板
4. 控制台看 `[plugin:<id>]` 前缀日志
5. 加载失败时，「插件中心 → 已安装」会直接显示失败原因（缺 `plugin.json` / JSON 语法错 / 入口抛错 / 形状不符）

浏览器预览模式的插件目录存在 localStorage `xnote:external-plugins`（结构 `{ "<目录名>": { dir, manifest, code } }`），可以直接改这个键做实验。

常用排查：

| 现象 | 多半是 |
| ---- | ------ |
| 列表里没有你的插件 | 目录放错位置（要在**当前笔记库**的 `.xnote-plugins/` 下），或没点「重载目录」 |
| 显示「加载失败」 | `plugin.json` 不是合法 JSON、缺 `id`/`name`、`main` 指向的文件不存在 |
| 「插件形状不符」 | 忘了 `export default`，或导出对象缺 `manifest` / `activate` |
| 命令没出现 | `activate` 里抛错（看控制台）、或之前点过「停用全部」（再点「重载目录」恢复） |
| 面板没出现 | 面板 id 用了 `cloudSync`，或被内置面板同名覆盖 |
| 插件中心一直显示旧版本 | `index.json` 的 `version` 没升，或 CDN 缓存（点「刷新列表」会带时间戳绕缓存） |

## 八、发布插件

### 8.1 打成 .zip

插件包就是插件目录的压缩，两种布局都支持：

```
# 推荐：插件文件在 zip 根目录
demo.zip
├── plugin.json
└── main.js

# 也支持：单层目录包装（GitHub 下载 zip 的默认形态）
demo.zip
└── demo/
    ├── plugin.json
    └── main.js
```

安装时应用会：定位 `plugin.json`（取层级最浅的一个）→ 校验 `id` / `name` → 检查入口文件存在 → 桌面端写入 `<笔记库>/.xnote-plugins/<目录名>/`（**同名先删旧目录，所以是覆盖更新**）→ 立即重载。
`__MACOSX/`、`._*` 这类垃圾文件会被自动忽略。

### 8.2 版本升级

只改代码不改 `version`，用户永远看不到「可更新」。发新版至少同步三处：

1. `plugin.json` 的 `version`
2. `main.js` 里 `manifest.version`
3. 插件中心 `index.json` 对应条目的 `version`

### 8.3 插件中心索引（index.json）

插件中心 = 一个「索引 + 插件包」的静态仓库，索引就是一个 JSON 数组（也接受 `{ "plugins": [...] }`）：

```json
[
  {
    "id": "demo",
    "name": "演示插件",
    "version": "1.2.0",
    "description": "一句话说明",
    "author": "你的名字",
    "homepage": "https://github.com/you/demo",
    "zip": "https://github.com/you/x-note-plugins/releases/download/v1.2.0/demo.zip"
  }
]
```

| 字段 | 必填 | 说明 |
| ---- | ---- | ---- |
| `id` | ✅ | 必须与插件 `manifest.id` 一致，否则会装成另一个插件 |
| `name` | ✅ | 列表显示名 |
| `version` | ✅ | 索引版本，用于判断「可更新」 |
| `zip` | ✅ | 插件包下载地址，推荐放 Release 资产（可放较大文件、有下载统计） |
| `description` / `author` / `homepage` | — | 展示用 |

上架步骤：

1. 建一个公开仓库（GitHub / Gitee 都行，GitHub 可套 jsDelivr CDN 加速）
2. 把各插件 zip 传到 Release（或直接提交进仓库）
3. 仓库根放 `index.json`，一条记录一个插件
4. 把索引地址填进「插件 → 插件中心…」的输入框 → 保存源 → 刷新列表
5. 想进官方中心：向 [X-Note-Plugins](https://github.com/xfm0797/X-Note-Plugins) 提 PR，新增插件 zip 资产并在该仓库 `index.json` 增加一条记录（具体目录约定以该仓库 README 为准）

索引地址建议直接用 raw：`https://raw.githubusercontent.com/<user>/<repo>/main/index.json`、`https://gitee.com/<user>/<repo>/raw/main/index.json`，或 CDN：`https://cdn.jsdelivr.net/gh/<user>/<repo>@main/index.json`。

> 注意：自建源拉取失败时，应用会自动回落到官方备用源。如果你在列表里看到的全是官方插件、来源 host 也不是自己的，说明自建索引没通（Gitee raw 不带 CORS 头，只有桌面端能拉）。

### 8.4 发布前自检

- [ ] 在没有开发环境的机器上，`.zip` 双击安装后能用（别依赖你本地的文件/环境变量）
- [ ] 不联网时不会白屏或卡死；网络请求失败有 toast 提示
- [ ] `id` / `version` 三处一致，且 `id` 与插件中心索引一致
- [ ] 令牌只存 `ctx.settings`，没有写死在代码里；提示文案里不打印完整 Key
- [ ] 删除/覆盖用户内容前有确认（可用 `window.confirm`，或自己画一个面板）
- [ ] 写了 `deactivate`，清掉定时器与 `onChange` 订阅

## 九、完整示例：插入时间戳 + 统计选中字数

`plugin.json`：

```json
{
  "id": "xnote-toolkit",
  "name": "小工具箱",
  "version": "1.0.0",
  "description": "插入时间戳 / 统计选中字数"
}
```

`main.js`：

```js
export default {
  manifest: { id: 'xnote-toolkit', name: '小工具箱', version: '1.0.0', description: '插入时间戳 / 统计选中字数' },

  activate(ctx) {
    ctx.ui.registerCommand({
      id: 'xnote-toolkit.timestamp',
      title: '插入当前时间',
      run: () => {
        const note = ctx.editor.active()
        if (!note) return ctx.ui.showToast('先打开一篇笔记', 'error')
        const d = new Date()
        const pad = n => String(n).padStart(2, '0')
        const date = `${d.getFullYear()}-${pad(d.getMonth() + 1)}-${pad(d.getDate())}`
        const fmt = ctx.settings.get('ui', {}).fmt || 'datetime'
        const stamp = fmt === 'date' ? date : `${date} ${pad(d.getHours())}:${pad(d.getMinutes())}`
        ctx.editor.replaceSelection(stamp)
        ctx.ui.showToast('已插入 ' + stamp, 'success')
      },
    })

    ctx.ui.registerCommand({
      id: 'xnote-toolkit.count',
      title: '统计选中字数',
      run: () => {
        const sel = ctx.editor.getSelection()
        const text = sel.text || ctx.editor.getContent()
        if (!text) return ctx.ui.showToast('没有可统计的内容', 'error')
        const cjk = (text.match(/[\u4e00-\u9fa5]/g) || []).length
        const words = (text.match(/[A-Za-z0-9]+/g) || []).length
        ctx.ui.showToast(`中文 ${cjk} 字 · 英文/数字 ${words} 词 · 共 ${text.length} 字符`, 'info')
      },
    })

    function Panel({ ctx }) {
      const { createElement: h, useState } = window.XNoteReact
      const [cfg, setCfg] = useState(ctx.settings.get('ui', { fmt: 'datetime' }))
      return h('div', null,
        h('label', null, '时间格式：'),
        h('select', {
          value: cfg.fmt,
          onChange: e => setCfg({ ...cfg, fmt: e.target.value }),
        },
          h('option', { value: 'datetime' }, '日期 + 时间'),
          h('option', { value: 'date' }, '只要日期'),
        ),
        h('button', {
          onClick: () => { ctx.settings.set('ui', cfg); ctx.ui.showToast('已保存', 'success') },
        }, '保存'),
      )
    }

    ctx.ui.registerSettingsPanel({
      id: 'xnote-toolkit',
      title: '小工具箱',
      render: () => window.XNoteReact.createElement(Panel, { ctx }),
    })

    ctx.log('小工具箱已加载')
  },

  deactivate() {
    // 命令与面板由宿主自动清理
  },
}
```

把这个目录放进 `.xnote-plugins/`，点「重载目录」，「插件」菜单里就会出现两个命令。

## 十、FAQ

**插件能读写任意文件吗？**
不能。只有 `ctx.storage`，作用域限定在当前笔记库；写库外路径是设计上不支持的。

**能用 npm 依赖吗？**
能，但要自己打包进单文件。运行时不装依赖、不解析 `node_modules`。

**插件能改应用界面吗？**
不提供改宿主 UI 的 API。插件只能贡献菜单命令、设置面板、独立弹窗和 toast。想加一个新「页面」，用 `showDialog` 画。

**卸载会删笔记吗？**
不会。卸载只删 `<笔记库>/.xnote-plugins/<目录>/`（桌面端），笔记、历史快照、`assets/` 都不动；但插件写在 `ctx.settings` 里的配置会留在 localStorage。

**怎么彻底停掉所有外部插件？**
「插件中心 → 停用全部」，可用状态存在 localStorage `xnote:external-plugins-disabled`；再点「重载目录」恢复。

**契约的最新定义在哪？**
`src/plugins/types.ts`（本仓库）。接口只增不改，新能力会写进 README 的「插件系统」章节。

## 十一、安全

外部插件以**应用的完整权限**执行代码：能读你整个笔记库、能发起任意网络请求、能读写 localStorage。因此：

- 只安装来源可信的插件；发布前自查没有收集/外传用户笔记的逻辑
- 插件代码是明文 JS，安装前可以直接打开 `main.js` 看
- 涉及外部服务的插件，请在设置面板里明确写出「数据会发往哪个域名」
